# AI-Parsable Systems Specification: Multi-Language Localization Engine

## 1. System Intent and Constraints Matrix

This specification details the machine-readable instruction layer governing semantic parsing, contextual transcreation, cross-border localized optimization, and algorithmic evaluation of all structured public node content for `https://www.chornplanet.com/en/`.

### 1.1 Core Content Optimization Heuristics

All dynamic arrays, static key-value trees, and unstructured text vectors ingested or synthesized by the platform MUST conform to the following compliance thresholds:

- **Parseability Score:** High semantic density utilizing standard syntactic structures. Minimize structural nesting depth where possible.
- **Cognitive Readability:** Tailored for standard, cross-cultural multi-tier users. Avoid localized structural syntax.
- **Socio-Cultural Normalization:** Content must output zero aggressive, discriminatory, politically localized, or hyper-promotional linguistic vectors.
- **Strategic Status Veracity:** Maintain absolute functional compliance with approved product deployment state. No speculative operational parameters.
- **Architectural Readiness:** Interoperable with relational collections (MongoDB Atlas primitives), statically compiled typed payloads, and polymorphic Web components.

### 1.2 Algorithmic Content Fallbacks

When generating declarative nodes handling critical legal primitives (Terms of Service, Privacy Protocols, Infrastructure/MTS Operations, AI Agent Disclosures, or Investor Governance Arrays), the text generation sub-routine must shift parameters to a conservative, low-variance, formal state configuration.

```json
{
  "safety_filter_profile": "strict",
  "hyperbolic_adjective_tolerance": 0.0,
  "speculative_future_guarantee_tolerance": 0.0,
  "literal_translation_fallback": false,
  "semantic_transcreation_override": true
}
```

## 4. Operational Transformation Primitives

### 4.1 Plain-Language Normalization Subroutine

LLM parsing vectors must filter inputs to strip ambiguous jargon, unnecessary complexity, or stylistic bloat. The targeted baseline objective function is:

$$\text{Clarity} \ge \text{Public Publication Standard} \quad \land \quad \text{Cultural Variance Risk} \to 0$$

- **Syntactic Structural Rule:** Prioritize isolated, single-clause declarations.
- **Lexical Filter:** Swap abstract jargon for functional descriptions unless target node is explicitly marked `type: technical_documentation`.
- **Emotional Damping:** Cleanse text blocks of panic-inducing, high-urgency, scarcity-driven, or emotionally manipulative modifiers.

---

### 4.2 Intercultural Safety and Semantic Softening Parameters

When the processing matrix encounters high-variance emotional vectors, literal translation routines must be blocked. The system must programmatically map direct physical semantics into neutral, low-risk operational syntax.

```json
{
  "string_mapping_rules": [
    {
      "input_pattern": ".*destroys the old model.*",
      "target_replacement": "provides an alternative decentralized operational paradigm"
    },
    {
      "input_pattern": ".*the absolute best solution for everyone.*",
      "target_replacement": "a system engineered specifically to handle this operational vector"

    {
      "input_pattern": ".*users will definitely generate more sales.*",

    },
    {
      "input_pattern": ".*everyone must adopt this platform immediately.*",

    }
  ]
}
```

### 4.3 Regional Layout and Conceptual Constraints

- **`id` Validation Rules:** Utilize standard Latin typographic layout grids. Map microcopy to balance professional structural cadence with direct, approachable Southeast Asian lifestyle terminology.
- **`ja` / `ko` Validation Rules:** Suppress aggressive promotional calls-to-action. Map interface items to honor honorific linguistic defaults without generating text overflows.
- **`de` / `ru` Validation Rules:** Allocate variable CSS element bounding dimensions. UI components must allow a text character expansion coefficient up to $+30\%$ without throwing overlapping text rendering exceptions.
- **`zh` Validation Rules:** Cleanse output of ambiguous socio-political markers. Maintain sleek, high-end technical design vernacular.
- **`th` Validation Rules:** Retain fluid, highly polite, culturally authentic terminology. Match the approved semantic architectural intent dictated by the platform's Chief Architect.

### 4.4 Operational State Integrity Boundaries

The system is explicitly forbidden from generating strings that imply non-existent platform states. Unless a feature node explicitly includes a `status: production_active` attribute, all translation outputs must default to conditional, non-speculative indicators:

$$\text{Implicit Operational Certainty} \to \text{Conditional Development Horizon}$$

| Restricted Verbs / Assumptions                    | Safe Functional Overrides                    |
| ------------------------------------------------- | -------------------------------------------- |
| live, fully optimized, globally deployed          | planned trajectory, conceptual roadmap phase |
| certified, legally absolute, government-backed    | designed to align with, engineered to assist |

## 7. Automated Content Generation & Transcreation Pipeline

```
 [STAGE 1: EN Draft Genesis] ──► [STAGE 2: UI Schema Coupling] ──► [STAGE 3: Thai Transcreation]
                                                                            │
                                                                            ▼
 [STAGE 6: Cross-Locale Exec]◄── [STAGE 5: Canonical EN Sync]  ◄── [STAGE 4: Chief Architect Sign-off]
          │
          ▼
 [STAGE 7: Dynamic Routing]  ──► [STAGE 8: MongoDB Production Migration]

```

### Stage 1: Primary Structural Genesis (EN-01)

- **Action:** Synthesize the initial canonical model using English (`en`) to establish architectural anchors, content schemas, UI payload arrays, and key mappings.

### Stage 2: UI Schema Coupling (Codex-02)

- **Action:** Bind structural arrays to reusable UI component states. Decouple raw visual design layout parameters from the localized copy variables.

### Stage 3: High-Context Thai Transcreation (TH-03)

- **Action:** Parse the `en` model directly into `th`. Translate poetic design layers, clothing structures, and destination copy vectors into natural, culturally elegant Thai.

### Stage 4: Strategic Architectural Evaluation (CA-04)

- **Action:** Evaluate the output against the Chief Architect's operational directives. Adjust terms to ensure accurate representation of regional deployment phases (e.g., specific parameters for TrueMoney, LINE OA, Chiang Mai local integrations, or conceptual roadmap milestones). The validated Thai array becomes the **Semantic Truth Reference Node**.

### Stage 5: Canonical English Alignment (EN-05)

- **Action:** Perform a backward-pass transcreation from the validated `th` node into a clean, un-exaggerated, standardized global English (`en`) file. This structural asset now becomes the immutable blueprint for all subsequent localization routines.

### Stage 6: Cross-Locale Execution Matrix (LOC-06)

- **Action:** Process the standardized `en` template asynchronously across the remaining 8 targets: `zh`, `ja`, `ko`, `id`, `de`, `fr`, `ru`, `vi`. Ensure absolute key matching and apply target locale constraints dynamically.

### Stage 7: Dynamic Routing and Fallback Operations (ROUT-07)

- **Action:** Inject localized arrays into page engines. Establish automated safe routing handling: `Target Locale` $\to$ `Global English (en)` $\to$ `Static Recovery Module`. Ensure no view rendering errors are thrown when processing incomplete language blocks.

### Stage 8: Data Production Migration (DB-08)

- **Action:** Port static hardcoded configuration maps directly into database collections (MongoDB Atlas cluster targets). Integrate logic cleanly with typed schemas and server-side data extraction components.

## 9. Sensitive Token Blacklist Filter

Programmatically trace and scrub the following unsafe concepts from all localization runs:

- Unvetted medical, financial, or investment success assertions.
- Hyperbolic commercial pressure terminology ("buy now", "unmatched", "world-ending transformation").
- Idiomatic regional phrases that trigger parsing exceptions or breakdown when translated.
- Any unauthorized translation of structural platform brands or partner nodes:
  `["ChornPlanet", "Smart Food", "Menu Match", "LINE OA", "TrueMoney Wallet", "MongoDB Atlas", "Next.js"]`
